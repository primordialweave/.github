# Security Policy

**Do not post vulnerability details, exploitable steps, secrets or private user data in a public issue.**

## Private disclosure
1. Visit the affected repository's **Security** tab.
2. If **Report a vulnerability** is offered, submit a private report there.
3. Otherwise open a public **non-sensitive** request asking maintainers to establish a private reporting channel; do **not** include exploit details.
4. Share versions, impact, reproduction and possible mitigations privately after a secure channel exists.

Each repository should state supported versions and maintenance status. This volunteer-run ecosystem cannot guarantee specific response times. Coordinate a responsible disclosure date with the affected maintainers before publication.

Never commit API keys, signing certificates or recovery codes. If a secret leaks, revoke and rotate it; deletion from the latest commit is not sufficient.
